= Découvrez les économies dans NetApp Workload Factory for Databases
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Explorez les économies dans NetApp Workload Factory for Databases pour vos charges de travail de base de données en comparant les coûts d'utilisation de Microsoft SQL Server sur Amazon Elastic Block Store (EBS), FSx for Windows File Server et le stockage sur site avec le stockage FSx for ONTAP.



[[about-this-task]]
== À propos de cette tâche

Vous pouvez explorer les économies pour vos charges de travail de base de données sur EBS, FSx for Windows File Server et le stockage sur site à l'aide du tableau de bord, de l'onglet Inventaire ou de l'onglet Explorer les économies. Dans tous les cas, vous pouvez utiliser le calculateur d'économies pour comparer les différents composants de coût liés à l'exécution de charges de travail Microsoft SQL Server, tels que le stockage, le calcul, la licence SQL, les instantanés et les clones, pour vos charges de travail de base de données sur les systèmes de fichiers FSx for ONTAP par rapport à Elastic Block Store (EBS), FSx for Windows File Server et le stockage sur site.

Si Workload Factory détecte des économies sur FSx for ONTAP, vous pouvez déployer Microsoft SQL sur FSx for ONTAP directement depuis le calculateur d'économies dans la console Workload Factory. Lorsque vous avez plusieurs instances Microsoft SQL Server sur Elastic Block Store, FSx for Windows File Server ou sur un stockage sur site, nous recommanderons une configuration FSx for ONTAP avec une seule instance SQL.

.Économies potentielles pour toutes les charges de travail de base de données
Consultez le tableau de bord *Dashboard* Bases de données dans la console Workload Factory pour obtenir un aperçu des économies potentielles liées à l'exécution de toutes vos charges de travail de base de données sur FSx for ONTAP. La vignette *Potential savings* affiche vos charges de travail de base de données sur EBS et FSx for Windows File Server, les économies potentielles, le pourcentage d'économies et un graphique à barres.

image:screenshot-dashboard-potential-savings-tile.png["Capture d'écran de la vignette « Économies potentielles » du tableau de bord des bases de données dans la console Workload Factory. La vignette « Économies potentielles » affiche le nombre total de charges de travail de base de données que vous avez sur Elastic Block Store et FSx for Windows File Server, les économies potentielles, le pourcentage d'économies et une représentation visuelle sous forme de graphique à barres."]

.Calculateur d'économies
Vous pouvez utiliser le calculateur d'économies pour comparer les différents éléments de coût liés à l'exécution de charges de travail Microsoft SQL Server, tels que le stockage, le calcul, la licence SQL, les instantanés et les clones, pour vos charges de travail de base de données sur les systèmes de fichiers FSx for ONTAP par rapport à Elastic Block Store (EBS), FSx for Windows File Server et le stockage sur site. Les systèmes de fichiers FSx for ONTAP peuvent être l'option la plus rentable pour vos charges de travail de base de données.

Le calculateur indique si le stockage des charges de travail de base de données sur ces serveurs Microsoft SQL coûterait moins cher si vous utilisiez un système de fichiers FSx for ONTAP. <<Options de la calculatrice,Découvrez comment utiliser la calculatrice.>>

image:screenshot-ebs-savings-calculator-update.png["Une capture d'écran de la page du calculateur d'économies affiche à gauche la configuration sélectionnée de Microsoft SQL Server sur Amazon Elastic Block Store, avec la possibilité de personnaliser les valeurs des instantanés et des clones. Les économies réalisées, exprimées en montant en dollars et en pourcentage, ainsi que le coût mensuel total de l'utilisation de Microsoft SQL Server sur FSx for ONTAP et du stockage Elastic Block Store, s'affichent à gauche."]



[[sql-server-deployment-analysis]]
== Analyse du déploiement de SQL Server

Le calculateur vérifie votre déploiement SQL Server pour s'assurer que les ressources et les fonctionnalités utilisées correspondent à l'édition SQL Server. Voici les principaux facteurs et conditions que le calculateur vérifie avant de recommander une rétrogradation vers l'édition Standard :

.Modèle de déploiement
Le calculateur évalue le modèle de déploiement et détermine si l’édition Enterprise est requise.

.Ressources allouées
Le calculateur évalue les conditions des ressources allouées suivantes qui dépendent de la licence :

* Processeurs virtuels (vCPU) de l'instance cible : L'instance possède 48 vCPU ou moins.
* Allocation de mémoire : L’instance dispose de 128GB ou moins de mémoire.


.Utilisation des fonctionnalités d'entreprise
Le calculateur vérifie si l’une des fonctionnalités Enterprise suivantes est utilisée :

* Fonctionnalités Enterprise au niveau de la base de données
* Opérations d'index en ligne
* Resource Governor
* Réplication de pair à pair ou Oracle
* extensions R/Python
* TempDB optimisé pour la mémoire


Si l'instance SQL Server évaluée n'utilise aucune des fonctionnalités Enterprise mentionnées ci-dessus et respecte les contraintes de ressources, le calculateur recommandera de passer à l'édition Standard. Le calculateur vous aide à optimiser les coûts de licence SQL Server sans réduire les performances ni la fonctionnalité.



[[calculator-options]]
== Options de la calculatrice

Deux options de calcul sont disponibles pour comparer les coûts entre vos systèmes et FSx for ONTAP : la personnalisation et la détection.

Explorez les économies possibles grâce à la personnalisation : vous fournissez les paramètres de configuration pour Microsoft SQL server sur Amazon EC2 avec EBS ou FSx for Windows File Server, notamment la région, le modèle de déploiement, l’édition de SQL server, le taux de modification mensuel des données, la fréquence des instantanés, et plus encore.

Découvrez les économies pour les hôtes détectés : Workload Factory se connecte à vos serveurs Microsoft SQL existants et importe les détails dans le calculateur pour une comparaison automatique. Vous devrez accorder les autorisations _view, planning, and analysis_ pour utiliser cette option du calculateur. Vous pouvez modifier le cas d’utilisation, mais tous les autres détails sont déterminés automatiquement dans le calcul.

De plus, vous pouvez link:../fsx-storage/add-credentials.html["ajouter les identifiants AWS"^] pour améliorer la précision de l’analyse du calculateur. Sélectionnez *Calculate savings based on existing resources*. Vous serez redirigé vers la page Add credentials. Après avoir ajouté les informations d’identification, sélectionnez les ressources existantes à comparer avec FSx for ONTAP, puis sélectionnez *Explore savings*.

[[explore-savings-for-detected-hosts]]
=== Découvrez les économies pour les hôtes détectés

Workload Factory intègre les caractéristiques de l'hôte détectées afin que vous puissiez explorer automatiquement les économies.

.Avant de commencer
Veuillez remplir les conditions préalables suivantes avant de commencer :

* link:../fsx-storage/add-credentials.html["Accorder les autorisations de _consultation, de planification et d'analyse_"^] dans votre compte AWS pour détecter les systèmes Elastic Block Store (EBS) et FSx for Windows sous l’onglet *Explorer les économies* et pour afficher le calcul des économies dans le calculateur d’économies.
* Pour obtenir des recommandations sur le type d'instance et améliorer la précision des coûts, procédez comme suit :
+
.. Accordez à Amazon CloudWatch et à AWS Compute Optimizer les autorisations.
+
... Connectez-vous à la console de gestion AWS et ouvrez le service IAM.
... Modifiez la stratégie du rôle IAM. Copiez et ajoutez les autorisations Amazon CloudWatch et AWS Compute Optimizer suivantes.
+
[source, json]
----
{
"Version": "2012-10-17",
"Statement": [
  {
   "Effect": "Allow",
   "Action": "compute-optimizer:GetEnrollmentStatus",
   "Resource": "*"
  },
  {
   "Effect": "Allow",
   "Action": "compute-optimizer:PutRecommendationPreferences",
   "Resource": "*"
  },
  {
   "Effect": "Allow",
   "Action": "compute-optimizer:GetEffectiveRecommendationPreferences",
   "Resource": "*"
  },
  {
   "Effect": "Allow",
   "Action": "compute-optimizer:GetEC2InstanceRecommendations",
   "Resource": "*"
  },
  {
   "Effect": "Allow",
   "Action": "autoscaling:DescribeAutoScalingGroups",
   "Resource": "*"
  },
  {
   "Effect": "Allow",
   "Action": "autoscaling:DescribeAutoScalingInstances",
   "Resource": "*"
  }
]
}
----


.. Inscrivez le compte AWS facturable à AWS Compute Optimizer.

Si Workload Factory détecte des hôtes EBS, il vous redirige vers l'onglet Explorer les économies. S'il ne détecte pas d'hôtes EBS, il vous redirige vers le calculateur pour <<Explorez les économies grâce à la personnalisation,explorez les économies grâce à la personnalisation>>.

. Dans *Explorer les économies*, sélectionnez un ou plusieurs hôtes de base de données exécutés sur EBS, puis sélectionnez *Explorer les économies*.
. Si nécessaire, authentifiez l’hôte de la base de données avec les identifiants Oracle, ou en ajoutant les autorisations Oracle manquantes.
+
Si la page Explore savings ne charge pas les données après une authentification réussie, sélectionnez l'onglet *Inventory* pour recharger les données, puis sélectionnez à nouveau l'onglet *Explore savings*.

. Dans le calculateur d'économies, vous pouvez fournir les détails suivants sur les clones et les instantanés de votre stockage EBS pour une estimation plus précise des économies.
+
.. *Fréquence de capture d'instantané*: Sélectionnez une fréquence de capture d'instantané dans le menu.
.. *Fréquence d'actualisation des clones* : Sélectionnez la fréquence d'actualisation des clones dans le menu.
.. *Nombre de copies clonées* : Saisissez le nombre de copies clonées dans la configuration EBS.
.. *Taux de modification mensuel* : saisissez le pourcentage moyen de modification mensuelle des données de clone et d’instantané.
.. *Ajouter des hôtes* : Vous pouvez sélectionner jusqu’à cinq hôtes EBS détectés à inclure dans le calcul des économies.
+
Workload Factory consolide plusieurs hôtes Oracle en une seule recommandation de configuration FSx for ONTAP afin d'optimiser les économies, sauf si les hôtes EBS sélectionnés dépassent les limites de débit, de capacité ou d'IOPS pour un seul système de fichiers FSx for ONTAP.

.Serveur Oracle sur site
--
.Étapes
. Connectez-vous au link:https://console.netapp.com["NetApp Console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet d'accéder à Workloads, l'élément de menu de Workload Factory"], *Charges de travail* > *Bases de données*.
. Dans le menu Bases de données, sélectionnez *Explorer les économies*.
. Dans Explorer les économies, sélectionnez le type de moteur *Microsoft SQL Server*.
. Ensuite, sélectionnez l'onglet *Oracle Server on-premises*.
. Dans l'onglet Oracle Server on-premises, sélectionnez *Assessment script* > *Assessment script information* et consultez les informations fournies.
. Sélectionnez *Download assessment script*.
+
Le script est un outil de collecte de données basé sur PowerShell. Il recueille les données de configuration et de performance du serveur Oracle.

. Exécutez le script sur l'hôte Oracle avec un utilisateur disposant de privilèges suffisants.
. Sélectionnez *Téléverser les résultats du script*, puis téléversez le fichier de sortie du script sur la console Workload Factory. L'outil d'aide à la migration analyse les données et planifie le déploiement de FSx for ONTAP pour votre environnement Oracle Server.
. Dans l'onglet Oracle Server sur site, sélectionnez Oracle Server sur site, puis sélectionnez *Explore savings* pour exécuter une analyse des coûts par rapport à FSx for ONTAP.
. Dans le calculateur d'économies, sélectionnez la région de l'hôte sur site.
. Vous pouvez également fournir les informations suivantes sur les clones (copies fantômes) et les instantanés dans votre environnement de base de données sur site pour une estimation plus précise des économies réalisées.
+
.. *Fréquence de capture d'instantané*: Sélectionnez une fréquence de capture d'instantané dans le menu.
+
Si Workload Factory détecte des shadow copies FSx for Windows, il définit la valeur par défaut sur *Quotidienne*. S'il ne détecte pas de shadow copies, il définit la valeur par défaut sur *Aucune fréquence de cliché instantané*.

.. *Fréquence d'actualisation des clones* : Sélectionnez la fréquence d'actualisation des clones dans le menu.
.. *Nombre de copies clonées* : Saisissez le nombre de copies clonées dans la configuration sur site.
.. *Taux de modification mensuel* : saisissez le pourcentage moyen de modification mensuelle des données de clone et d’instantané.


. Pour des résultats plus précis, mettez à jour les informations de calcul ainsi que les détails relatifs au stockage et aux performances.
+
Workload Factory consolide plusieurs bases de données Oracle sur site en une seule recommandation de configuration FSx for ONTAP afin d’optimiser les économies, sauf si les bases de données sur site sélectionnées dépassent les limites de débit, de capacité ou d’IOPS pour un seul système de fichiers FSx for ONTAP.



.Suppression de l'hôte sur site
Après avoir exploré les économies pour un hôte Oracle sur site, vous avez la possibilité de supprimer l'enregistrement de l'hôte sur site dans Workload Factory. Sélectionnez le menu d'actions de l'hôte Oracle sur site, puis sélectionnez *Supprimer*.

== Déployer Microsoft SQL Server sur AWS EC2 à l'aide de FSx for ONTAP

Si vous souhaitez passer à FSx for ONTAP afin de réaliser des économies, cliquez sur *Create* pour créer la ou les configurations recommandées directement à partir de l’assistant Create new Microsoft SQL server wizard ou cliquez sur *Save* pour enregistrer la ou les configurations recommandées pour une utilisation ultérieure.


NOTE: Workload Factory ne prend pas en charge l'enregistrement ou la création de plusieurs systèmes de fichiers FSx for ONTAP.

.Méthodes de déploiement
Avec les autorisations de _création d'hôte de base de données_, vous pouvez déployer le nouveau serveur Microsoft SQL sur AWS EC2 à l'aide de FSx for ONTAP directement depuis Workload Factory. Vous pouvez également copier le contenu de la fenêtre Codebox et déployer la configuration recommandée à l'aide de l'une des méthodes Codebox.

Sans les autorisations requises, vous pouvez copier le contenu de la fenêtre Codebox et déployer la configuration recommandée à l’aide de l’une des méthodes Codebox.
