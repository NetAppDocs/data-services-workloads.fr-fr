= Implémentez des configurations de base de données bien architecturées dans NetApp Workload Factory
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
En utilisant les analyses de configuration et les recommandations, exploitez NetApp Workload Factory pour mettre en œuvre les meilleures pratiques pour vos configurations de base de données avec Microsoft SQL Server et Oracle. Vous pouvez facilement vérifier l’état bien architecturé, découvrir les problèmes liés aux configurations de base de données et corriger les configurations qui ne sont pas optimisées pour la fiabilité, la sécurité, l’efficacité, la performance et le coût.

Vous pouvez également ignorer l'analyse des configurations qui ne s'appliquent pas à votre environnement afin d'éviter des alertes supplémentaires et des résultats inexacts.

link:optimize-overview.html["Découvrez l'analyse de la configuration et l'état bien architecturé dans Workload Factory."]



[[about-this-task]]
== À propos de cette tâche

Workload Factory analyse quotidiennement les configurations de base de données. L'analyse quotidienne fournit un état bien architecturé, des informations et des recommandations.

De nombreuses recommandations sont disponibles lorsque vous accordez les autorisations _view, planning, and analysis_ à votre compte AWS. Si vous accordez les autorisations _operations and remediation_, toutes les recommandations sont disponibles et vous pouvez corriger automatiquement les problèmes de configuration afin de respecter les bonnes pratiques.

Vous pouvez consulter et corriger les problèmes depuis l'inventaire des bases de données ou le tableau de bord « Architecture optimisée » de la console Workload Factory. Comme les exigences de configuration des bases de données varient, vous pouvez ignorer l'analyse des configurations spécifiques qui ne s'appliquent pas à votre environnement de base de données. Cela vous permet d'éviter les alertes inutiles et les résultats d'optimisation erronés.

Vous pouvez également effectuer une évaluation ponctuelle pour examiner les meilleures pratiques pour la configuration de votre base de données, sans avoir à stocker d'identifiants ni à enregistrer de ressources.

Vous pouvez également créer des règles personnalisées en langage clair pour valider vos environnements par rapport aux normes de votre organisation et aux bonnes pratiques NetApp. Testez les règles à blanc, puis planifiez leur exécution dans vos environnements. link:../fsx-storage/learn-custom-rules.html["En savoir plus sur les règles personnalisées."^]

.Ce qui est analysé
Workload Factory analyse l’état « well-architected » des configurations suivantes :

Pour les instances Microsoft SQL Server :

* Dimensionnement du stockage : comprend le niveau de stockage, la marge du système de fichiers, la taille du disque de journalisation et la taille du disque TempDB
* Organisation du stockage : comprend l’emplacement des fichiers de données utilisateur, des fichiers journaux et de TempDB
* Configuration du stockage : inclut la gestion de la capacité, le provisionnement fin, la stratégie de hiérarchisation, les instantanés, l’état des E/S multipath Microsoft (MPIO) et le paramètre de délai d’expiration MPIO
* Calcul : inclut le dimensionnement approprié, les correctifs du système d’exploitation et les paramètres de la carte réseau tels que la mise à l’échelle côté réception (RSS), le déchargement TCP et l’alignement MTU
* Application : inclut les licences Microsoft SQL Server, le correctif Microsoft SQL Server et les paramètres MAXDOP
* Résilience : inclut les instantanés locaux, la configuration de sauvegarde, la réplication interrégionale (CRR), la haute disponibilité Microsoft SQL et le nettoyage des clones
* Clones : incluent des options pour actualiser et supprimer les clones (environnements de test) créés dans ou en dehors de Workload Factory et datant de plus de 60 jours


Pour les bases de données Oracle :

* Dimensionnement du stockage : comprend l’allocation de l’espace d’échange et la marge disponible du système de fichiers
* Configuration du stockage : comprend la gestion de la capacité, le provisionnement fin, la politique de hiérarchisation, les instantanés, les optimisations du stockage et les configurations du système d’exploitation pour les déploiements utilisant NFS ou iSCSI avec ou sans Automatic Storage Management (ASM), y compris l’état et les paramètres de Microsoft Multipath I/O (MPIO), ainsi que les paramètres dNFS suivants : activation de dNFS, résolution IP cohérente dNFS, fichier de configuration dNFS, et dNFS `nosharecache`
* Agencement du stockage : comprend l’emplacement des journaux redo, des espaces de table temporaires, des fichiers de données, des journaux d’archivage, des fichiers de contrôle et des fichiers binaires, ainsi que le nombre de LUN des groupes de disques ASM
* Calcul : inclut les correctifs du système d’exploitation
* Application : inclut les mises à jour critiques d’Oracle
* Résilience : comprend la réplication interrégionale (CRR), les instantanés cohérents au niveau des applications, la configuration de sauvegarde et le nettoyage des clones


L'analyse bien architecturée pour Oracle vous avertit lorsqu'une configuration dépend d'autres et répertorie les actions pour optimiser les configurations liées.



[[perform-a-one-time-assessment-of-your-configurations]]
== Effectuez une évaluation unique de vos configurations

Effectuez une évaluation ponctuelle pour connaître l'état d'architecture de vos instances Microsoft SQL Server ou de vos bases de données Oracle sans stocker d'informations d'identification ni enregistrer de ressources.

Vous pouvez exécuter le script et importer les résultats plusieurs fois. Workload Factory met à jour le statut bien architecturé et les insights à chaque importation.

Pour chaque configuration, vous pouvez consulter la valeur actuelle et la valeur recommandée.

[role="tabbed-block"]
====
.Instances Microsoft SQL Server
--
.Étapes
. Connectez-vous en utilisant l'un des link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["expériences sur console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet de naviguer vers des charges de travail telles que le stockage, eda, ai, bases de données, vmware et l'administration."] puis sélectionnez *Bases de données*.
. Dans l'*Inventaire*, sélectionnez *SQL Server* comme type de moteur.
. Sélectionnez *Évaluation ponctuelle* > *En savoir plus sur l'évaluation*. Consultez les informations relatives à l'évaluation ponctuelle.
. Sélectionnez *Download script*.
+
.. Copiez le script sur votre hôte Microsoft SQL Server.
.. Exécutez le script dans PowerShell. Un seul script collecte les métadonnées de toutes les instances.


. Sélectionnez *Évaluation ponctuelle* > *Téléverser*. Trouvez le fichier et téléversez-le sur la console Workload Factory.
. Consultez les recommandations pour chaque configuration. Workload Factory inclut les bonnes pratiques et les problèmes potentiels dans ses recommandations si les configurations ne sont pas optimisées.


--
.bases de données Oracle
--
.Étapes
. Connectez-vous en utilisant l'un des link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["expériences sur console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet de naviguer vers des charges de travail telles que le stockage, eda, ai, bases de données, vmware et l'administration."] puis sélectionnez *Bases de données*.
. Dans l'*Inventaire*, sélectionnez *Oracle* comme type de moteur.
. Sélectionnez *Évaluation ponctuelle* > *En savoir plus sur l'évaluation*. Consultez les informations relatives à l'évaluation ponctuelle.
. Sélectionnez *Download script*.
+
.. Copiez le script Python sur votre hôte de base de données Oracle.
.. Exécutez le script dans l'interpréteur de commandes approprié. Un seul script collecte les métadonnées de toutes les bases de données.


. Sélectionnez *Évaluation ponctuelle* > *Téléverser*. Trouvez le fichier et téléversez-le sur la console Workload Factory.
. Consultez les recommandations pour chaque configuration. Workload Factory inclut les bonnes pratiques et les problèmes potentiels dans ses recommandations si les configurations ne sont pas optimisées.


--

[[perform-an-on-demand-assessment]]
== Effectuer une évaluation à la demande

Si vous accordez les autorisations _opérations et remédiation_ à votre compte AWS, vous pouvez effectuer une évaluation à la demande de vos bases de données Oracle. Vous n'avez pas besoin d'enregistrer de ressources pour exécuter cette évaluation.

.Étapes
. Connectez-vous en utilisant l'un des link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["expériences sur console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet de naviguer vers des charges de travail telles que le stockage, eda, ai, bases de données, vmware et l'administration."] puis sélectionnez *Bases de données*.
. Dans l'*Inventaire*, sélectionnez *Oracle* comme type de moteur.
. Sélectionnez *Afficher et corriger*.
. Dans l'onglet Well-architected status, sélectionnez *Analyser maintenant*.
. Consultez les recommandations pour chaque configuration. Workload Factory inclut les bonnes pratiques et les problèmes potentiels dans ses recommandations si les configurations ne sont pas optimisées.




[[before-you-begin-fixing-dismissing-and-re-activating-configurations]]
== Avant de commencer à corriger, à ignorer et à réactiver les configurations

Les exigences suivantes sont nécessaires pour l'évaluation continue de votre environnement de base de données et la correction automatique des problèmes de configuration. Ces exigences ne sont pas requises pour l'évaluation ponctuelle.

* Vous devez link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["accorder les autorisations d'_opérations et de remédiation_"^] dans votre compte AWS.
* Vous devez enregistrer la ressource dans Workload Factory et le type de stockage doit être FSx pour ONTAP. link:register-instance.html["Découvrez comment enregistrer des ressources."]
* Examinez chaque recommandation avant de modifier un paramètre ou une configuration. Pour RSS et MAXDOP, testez les paramètres recommandés pour vérifier les performances avant de modifier votre environnement de production.




[[fix-a-configuration-issue]]
== Résoudre un problème de configuration

Corrigez les problèmes de configuration des environnements SQL Server ou Oracle exécutés sur le stockage FSx for ONTAP.


NOTE: La modification d'une configuration peut entraîner des interruptions ou une interruption de service. Veuillez examiner attentivement la recommandation avant de procéder à toute modification de configuration.

.Étapes
. Connectez-vous en utilisant l'un des link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["expériences sur console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet de naviguer vers des charges de travail telles que le stockage, eda, ai, bases de données, vmware et l'administration."] puis sélectionnez *Bases de données*.
. Dans l'*Inventaire*, sélectionnez le type de moteur : Microsoft SQL Server ou Oracle.
. Sélectionnez les ressources à corriger pour des configurations spécifiques.
+
** Si vous avez sélectionné Microsoft SQL Server, sélectionnez l'onglet *Instances*.
** Si vous avez sélectionné Oracle, sélectionnez l'onglet *Bases de données*.


. Sélectionnez *Afficher et corriger* pour consulter les problèmes de configuration de l'instance.
. Sur la page d'état « Bien architecturée » de l'instance, consultez les résultats de l'analyse.
+
Vous pouvez filtrer les problèmes de configuration par catégories, sous-catégories, statut, gravité et étiquettes.

+
Sélectionnez *Export PDF* pour télécharger un rapport des résultats.

. Sélectionnez la flèche déroulante pour afficher la recommandation relative à chaque configuration. Les recommandations comprennent les bonnes pratiques, les pièges potentiels des configurations non optimisées et les points importants à prendre en compte. Assurez-vous d’examiner attentivement la recommandation.
. Sélectionnez cette option pour *afficher et corriger* les problèmes de configuration lorsque l’option est disponible.
+
L'option *Tout sélectionner* est sélectionnée par défaut, mais vous pouvez sélectionner des ressources spécifiques à corriger.

+
.. Pour toutes les configurations, à l'exception du nettoyage des clones, consultez les détails de la recommandation afin d'évaluer l'impact de la résolution du problème. Certaines opérations de correction peuvent entraîner une interruption ou des interruptions de service.
.. Pour le nettoyage des clones, sélectionnez les bases de données clonées (sandboxes) à actualiser ou à supprimer.
+
*** L'actualisation d'un clone le synchronise avec sa base de données. L'actualisation est disponible uniquement pour les clones créés dans Workload Factory.
*** La suppression d'un clone le supprime définitivement, libère de l'espace de stockage et réduit les coûts. Vous pouvez supprimer les clones créés dans et en dehors de Workload Factory.




. Sélectionnez *Continuer* pour résoudre le problème de configuration.


.Résultat
Workload Factory commence à résoudre le ou les problèmes. Sélectionnez l'onglet *Surveillance des tâches* pour consulter l'état de l'opération.



[[dismiss-the-analysis-of-database-configurations]]
== Rejeter l'analyse des configurations de base de données

Ignorez l'analyse des configurations de base de données spécifiques qui ne s'appliquent pas à votre environnement de base de données afin d'éviter les alertes inutiles et des résultats d'optimisation inexacts. Vous pouvez réactiver une analyse de configuration ignorée à tout moment.

.Étapes
. Connectez-vous en utilisant l'un des link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["expériences sur console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet de naviguer vers des charges de travail telles que le stockage, eda, ai, bases de données, vmware et l'administration."] puis sélectionnez *Bases de données*.
. Dans le menu Bases de données, sélectionnez *Inventaire*.
. Dans l’inventaire, sélectionnez le type de moteur de base de données : *Microsoft SQL Server* ou *Oracle*.
. Accédez à l’instance SQL Server ou à la base de données Oracle dont la configuration doit être reportée, sélectionnez le menu Actions, puis sélectionnez *Well-architected*.
. Sur la page d’analyse Well-architected, faites défiler vers le bas jusqu’à la configuration à reporter, sélectionnez le menu d’actions, puis sélectionnez *Ignorer*.
. Dans la boîte de dialogue de configuration du rejet, sélectionnez l’option *Dismiss*, puis sélectionnez *Dismiss* pour confirmer le rejet.


.Résultat
Workload Factory interrompt l'analyse de configuration.

Vous pouvez réactiver l'analyse à tout moment. La configuration n'est plus prise en compte dans le score d'optimisation total.



[[reactivate-a-dismissed-configuration-analysis]]
== Réactiver une analyse de configuration rejetée

Vous pouvez réactiver à tout moment une analyse de configuration annulée. Vous pouvez sélectionner une ou plusieurs configurations à réactiver.

.Étapes
. Connectez-vous au link:https://console.netapp.com["NetApp Console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet d'accéder à Workloads, l'élément de menu de Workload Factory"], *Charges de travail* > *Bases de données*.
. Dans le menu Bases de données, sélectionnez *Inventaire*.
. Dans l’inventaire, sélectionnez le type de moteur de base de données : *Microsoft SQL Server* ou *Oracle*.
. Accédez à l’instance SQL Server ou à la base de données Oracle dont la configuration doit être reportée, sélectionnez le menu Actions, puis sélectionnez *Well-architected*.
. Sur la page d’analyse Well-architected, sélectionnez *Dismissed configuration* pour afficher uniquement les configurations rejetées.
. Sélectionnez *Réactiver* pour redémarrer l’analyse de la configuration reportée ou ignorée.


.Résultat
Workload Factory réactive l'analyse de configuration et l'exécute désormais quotidiennement.
